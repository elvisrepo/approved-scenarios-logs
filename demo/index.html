    Approved Scenarios

    Readable examples.
    Executable expectations.

    Each file is input + expected output in domain language. Pick a file to view it exactly as the runner sees it.

    How these files get tested

    The runner (tests/scenarios.test.ts, full source in the Source code tab) discovers every scenarios/*.approved.md at collection time — a new test case is a new file, this code never changes. Per file, three steps:

    1. Parse (scenarios.test.ts:23) — parseScenario reads the input and demands a ## Result; hollow files throw here, before the code runs.
    2. Execute (scenarios.test.ts:26) — mergeSleep runs on the file's input.
    3. Render + diff (scenarios.test.ts:30) — the actual result is rebuilt into the same markdown and compared to the file in the suite's only assertion.
